# Triply

Приложение для совместных поездок: друзья скидываются на общие расходы, а Triply
в конце считает, кто кому сколько должен перевести.

## Запуск

Нужны Node 22+ и Docker.

```bash
cp .env.example .env      # значения по умолчанию уже рабочие
docker compose up -d      # Postgres на localhost:5433 и почта на localhost:8025
npm install
npx prisma migrate dev    # схема и клиент
npm run seed              # демо-данные (по желанию)
npm run dev               # http://localhost:3000
```

Письма приложение шлёт в Mailpit из `docker-compose.yml` — открыть ящик можно на
http://localhost:8025. Через него проходят восстановление пароля и подтверждение
новой почты. Если `MAIL_SMTP_HOST` не задан, письмо просто печатается в консоль
сервера: ссылку из него видно и там, поэтому оба сценария работают и без
почтового сервера.

После `npm run seed` можно войти как `anna@triply.test`, `boris@triply.test` или
`vera@triply.test` — пароль у всех `password123`. В базе появится поездка на
троих с гостем и четырьмя расходами, включая расход с ручными долями и расход,
который оплатил не участвовавший в нём человек.

## Тесты

`npm test` гоняет две разные вещи. Расчётное ядро, деньги, даты и почта —
обычные юнит-тесты без окружения. Права серверных действий — тесты с настоящим
Postgres: подменять клиент базы там нечем, потому что проверка «чужую поездку не
тронуть» и есть запрос.

Поэтому тестам нужна поднятая база (`docker compose up -d db`). Берут они
соседнюю, `triply_test`: заводят её сами, накатывают миграции и чистят таблицы
перед каждым тестом — база разработки не страдает. Другой адрес задаётся
переменной `TEST_DATABASE_URL`; совпадение с `DATABASE_URL` тесты отвергают.

## Выкат

Vercel Hobby, база в Timeweb Cloud, домен `gettriply.ru`, письма через smtp.bz.
Платит проект только за базу и домен: бесплатные Postgres из России недоступны.
Выкат идёт по push в `main`: Vercel собирает проект командой из `vercel.json`,
она же накатывает миграции. Что завести и какие переменные задать —
`docs/deploy.md`.

`.github/workflows/ci.yml` на каждый pull request гоняет `lint`, `typecheck` и
`test` — с настоящим Postgres в сервисном контейнере, иначе тесты на права не
прогонятся.

## Как устроено

- `src/lib/settlement/` — расчётное ядро: деление расходов, балансы участников,
  минимизация числа переводов. Чистые функции без БД и React, покрыты тестами.
- `src/lib/actions/` — серверные действия: здесь проверяются права, и рядом
  лежат тесты на них.
- `src/lib/trips/invite-link.ts` — приглашение по ссылке: что ссылка делает с
  тем, кто её открыл. Сама страница — `src/app/join/[token]`.
- `src/test/` — обвязка тестов с базой: тестовая база, фабрики данных и всё, чего
  вне запроса Next не существует.
- `src/lib/money.ts` — деньги: суммы везде хранятся целыми минорными единицами
  (копейками), форматирование и разбор ввода собраны здесь.
- `src/lib/mail/` — письма: сборка MIME и свой маленький SMTP-клиент.
- `prisma/schema.prisma` — модель данных.
- `src/app/` — маршруты и страницы.

Подробности решений — в `CLAUDE.md`, план развития — в `docs/roadmap.md`,
выкат — в `docs/deploy.md`.
